# Models

Single source of truth for adapters approved for use in this project.

All model weights live on the Hugging Face Hub under the `GDGBabcockUniversity-26` organization. They are never stored in this Git repository. Adapters are referenced by Hugging Face repository ID plus a subfolder, never by file path.

Every approved entry is an **adapter**, not a merged model. The base model is fixed project-wide and lives separately. See the next section.

Contributors do not edit this file. A maintainer adds one row at merge time, after the PR passes CI and review. The PR label `approved` marks the merge.

## What is an adapter? (for contributors new to fine-tuning)

The base model, `facebook/nllb-200-distilled-1.3B`, already knows general translation. Fine-tuning with LoRA or QLoRA — these are just memory-efficient ways of fine-tuning a large language model — does not retrain the whole model. It trains a small set of extra weights that sit on top of the base model and nudge its behavior toward what you trained it on: better English→French translation.

That small set of extra weights is the **adapter**. It is not a standalone model. On its own it does nothing. At inference time, you load the full base model, then load the adapter on top of it, and the combination is what produces the translation.

**Why do it this way instead of saving the whole retrained model?**

- **Size.** An adapter is often a few MB. The full base model is several GB. Pushing and pulling adapters to the HF Hub is fast; pushing full models is not.
- **Speed.** Training only the adapter weights is far cheaper than retraining 1.3 billion parameters.
- **Swappability.** Multiple contributors each train their own adapter on the same base model. The backend just swaps which adapter it loads. No one re-uploads the base model.

So: **base model = the general translator. Adapter = the small "French improvement" bolted onto it.** You always need both to run inference. The adapter alone is not a working model.

## Fixed base model

Every adapter in this project targets one base model:
### facebook/nllb-200-distilled-1.3B


This is fixed. Do not train against a different base. If you do, the backend cannot swap your adapter with the others, and your submission is rejected.

The base model is defined once in code as `BASE_MODEL` in `backend/config.py`. Nothing in this registry replaces it.

## What is COMET?

COMET (Crosslingual Optimized Metric for Evaluation of Translation) is the metric this project uses to decide whether an adapter is better than the base model.

It is not a formula you can compute by hand. It is a small neural network, trained on thousands of human quality judgments of translations. You give it three things:

- the English source sentence
- the French translation being judged — what the base model or the fine-tuned adapter produced
- a correct French translation — the **reference** it is scored against

It returns a single number, roughly between 0 and 1. Higher is better. The number is not a percentage. A score of 0.85 versus 0.87 is a real difference in quality.

COMET correlates with human judgment better than older metrics, which is why it is the only metric this project accepts.

**The COMET checkpoint is pinned.** Several versions exist — `wmt20-comet-da`, `wmt22-comet-da`, and others — and they produce different numbers on the same translations. The project uses one. The pinned checkpoint is set in `training/eval.ipynb`. Scores from a different checkpoint are not comparable and are not accepted.

## What is the held-out test set?

The held-out test set is a slice of the dataset never shown to the model during training. Not once. It is kept aside so that evaluation measures translation on sentences the model has never seen.

If you evaluated on sentences the model trained on, the score would be meaningless — the model would be reciting, not translating.

The test set must contain reference French translations, because COMET needs a reference to score against.

**The base model and every fine-tuned adapter are evaluated on the same test set.** Same English sentences, same French references, same COMET checkpoint. This is what makes the comparison fair. If two models are evaluated on different sentences, their scores cannot be compared and the registry becomes meaningless.

The test set is fixed project-wide, has a known row count, and that count is recorded in each registry row.

The comparison works like this:

1. Load the base model alone. Translate the test set. Score with COMET. → **base number**
2. Load the base model plus your adapter. Translate the same test set. Score with COMET. → **your number**
3. If your number is higher, your adapter improved English→French translation.

That pair of numbers is what you report in your PR.

## Model Requirements

A model submission must never be a bare model-weight upload, and must never be a merged model.

Every submitted adapter must include:

- Hugging Face adapter repo ID and subfolder, under `GDGBabcockUniversity-26/english_to_french_nmt_adapters`
- The exact base model the adapter was trained against
- Training notebook
- Notebook settings
- Dataset used — one already listed in `DATASETS.md`
- Evaluation notebook
- COMET score for the base model and for the fine-tuned model (base model + adapter), on the same test set

**Submissions must be adapter weights only.** Do not push merged weights. Do not push the full fine-tuned model. The base model is downloaded from the official NLLB repository at inference time and is never re-uploaded by contributors.

Model weights must not be committed to Git.

## How a model is evaluated

Every submitted adapter is evaluated using `training/eval.ipynb`, against the project's held-out test set.

Evaluation loads the base model plus the submitted adapter, the same way the backend loads them. COMET numbers reported from a merged model are not accepted. They must come from the base-plus-adapter pair.

Model acceptance is based on reproducible numbers, not subjective comparison.

An adapter is approved if its COMET score meets or improves on the current best score in the registry, or if the project owner explicitly accepts it as an alternative worth keeping for comparison.

## How to Add a Model

1. Open `training/train.ipynb` on Kaggle (or locally if you have a GPU). Edit the settings cell at the top to set your dataset, adapter name, and hyperparameters. Run all cells. Train against `facebook/nllb-200-distilled-1.3B`.
2. Save the adapter only — LoRA or QLoRA weights, not a merged model.
3. Upload the adapter to the Hugging Face Hub under `GDGBabcockUniversity-26/english_to_french_nmt_adapters`, in a subfolder you name.
4. Open `training/eval.ipynb` and run all cells. It reports both the base number and your number.
5. Open a pull request containing:
   - Training notebook
   - Notebook settings
   - Dataset reference — a dataset already listed in `DATASETS.md`
   - Evaluation notebook
   - COMET score for your adapter and for the base model on the same test dataset
   - Hugging Face adapter link
6. CI verifies that the base model loads, that the adapter loads on top of it, and that the eval script runs.
7. A maintainer reviews the submission per the review tiers in `CONTRIBUTING.md`.
8. On merge, the maintainer applies the `approved` label and adds one row to the registry below.

The subfolder name in the adapter repo is assigned by the maintainer at merge time. Propose a name in your PR; the maintainer assigns the final name. Do not assume your submission keeps the subfolder you propose.

Do not add a row to the registry yourself. Do not add a status column. If a submission is rejected, no row is added — the closed PR is the record.

## Loading an Approved Model

Approved adapters load in two steps: the base model first, then the adapter on top. Plain `AutoModelForSeq2SeqLM.from_pretrained(adapter_repo, subfolder=adapter_subfolder)` does **not** work — an adapter repo does not contain a full model.

```python
from transformers import AutoModelForSeq2SeqLM, AutoTokenizer
from peft import PeftModel

base_id = "facebook/nllb-200-distilled-1.3B"   # fixed project base model
adapter_repo = "GDGBabcockUniversity-26/english_to_french_nmt_adapters"
adapter_subfolder = "submission-001"

tokenizer = AutoTokenizer.from_pretrained(base_id)
base = AutoModelForSeq2SeqLM.from_pretrained(base_id)
model = PeftModel.from_pretrained(
    base,
    adapter_repo,
    subfolder=adapter_subfolder,
)
```
`peft` is required for loading. It is listed in the project requirements files.

For NLLB models, the tokenizer must use the appropriate NLLB language codes for English and French: `eng_Latn` and `fra_Latn`.

## Model Rules

- Never commit model weights to Git.
- Store adapters on the Hugging Face Hub. Never push merged or full model weights.
- Register each approved adapter as one row in this file. Only a maintainer adds rows.
- Do not register the same adapter subfolder more than once.
- Keep the exact base model documented. All adapters must target `facebook/nllb-200-distilled-1.3B` so the backend can swap them freely.
- Keep training notebook settings reproducible.
- Keep evaluation results reproducible. Always report the base number alongside the adapter number, from the same test set and the same COMET checkpoint.
- Do not silently replace the weights of an approved adapter. Upload a new subfolder and open a new PR.
- Approved adapters are not deleted from the registry. If an adapter should no longer be used, the maintainer marks it in the PR that deprecates it. The row stays for reproducibility.
- Every row records both COMET numbers and both dataset row counts. A submission missing any of them is incomplete.
- The backend reads its adapter repo ID and subfolder from `.env`. Both must match a row in this registry.
